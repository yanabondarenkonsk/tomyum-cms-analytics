# Проверка итогового комплекта

12 октября 2026 · версия 1.1.

## Проверено

- Синтаксис JavaScript итогового HTML.
- Деньги из независимого демонабора: август — 8 оплат на 8 400 ₽, сентябрь — 5 оплат на 5 500 ₽.
- Фильтр iOS для сентября даёт 3 оплаты на 3 300 ₽; фильтр ресторана возвращает только соответствующие записи.
- В сентябре 12 активных участников, из них 11 с CRM ID и 1 анонимный. Список CRM ID без повторов.
- Первый и второй заказ не подменяются открытием приложения. Незрелое окно когорты не отображается нулём.
- Демо-генератор создаёт настоящий XLSX. Полученный ZIP-пакет проверен на CRC; независимый openpyxl открывает книгу и листы.
- Длинный ID `12345678901234567890`, ID с начальными нулями `000123` и строка `=1+1` сохранены текстом: нет округления, потери нулей или исполнения формулы.
- Условия Excel включают период, контекст когорты/сегмента, отбор результата, поиск ID, окно/правило, часовой пояс и дату среза.
- Наличие необходимых разделов в ТЗ: идентификация, XLSX, выборки клиентов, типы сегментов, передача, исключения и проверяемая приёмка.

## Ограничения проверки

В среде подготовки нет установленного браузера для Playwright. Не проведена полноценная проверка рендеринга и кликов в браузере. Синтаксис, расчёты и создание XLSX проверены отдельно; перед утверждением нужен ручной проход сценариев из README на desktop и мобильном экране.

## Граница макета и реализации

- Макет локальный и демонстрационный; сегменты и виджеты хранятся в памяти до закрытия страницы.
- Фильтры реальны для демонабора. Когорта августа имеет собственное основание и срез; выбранный общий месяц относится к событиям/оплатам и подписан отдельно.
- Воронка макета показывает пересечение участников событий за месяц. В production нужны порядок, окно и связи сущностей из ТЗ.
- Корзины в демонаборе сравниваются с оплатой в месяце. Production-корзины без оплаты должны рассчитываться по зрелому окну 24 часа, отдельно от оперативного триггера 15 минут.
- Статусы платёжного провайдера, возвраты, точные добавки, видимость/клики баннеров и время экранов не выдумываются. Их источники указаны как требующие подтверждения.
- Динамический сегмент демонстрирует сохранение условий, но не запускает фоновый пересчёт.
- Переход в существующие рассылки — заглушка с ID сегмента; сообщения и API-запросы не отправляются.
- Серверные роли, пагинация больших наборов, фоновые выгрузки, версии определений, актуальные разрешения канала и проверки оплаты перед отправкой — требования к разработке, а не реализованные возможности макета.

## Проверка перед обсуждением

Программисту нужно пройти README и отметить реализуемость источника/параметра для каждого отчёта. Утвердить формулы и окна до программирования витрин. По каждому пункту без данных согласовать доработку источника, а не заменять отсутствие нулём.
